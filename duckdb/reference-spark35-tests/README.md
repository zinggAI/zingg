# Spark 3.5.5 differential reference tests

2026-09-29 `show` output follow-up: changed the four ZFrame `show` overload checks from marker-only assertions to full normalized-console equality against Spark `showString`. This exposed and fixed incompatible table borders/alignment, truncation behavior, unconditional footer output, and missing singular/plural wording. Exact output comparisons now cover default `show()`, `show(boolean)`, `show(int)`, `show(int,boolean)`, zero/negative/one-row limits, empty and zero-column relations (including row-count preservation), 21 rows shown at the default limit, NULL/control-character escaping, and duplicate display-column names. The opt-in differential passed **1/1 on Windows** and **1/1 on WSL2**; WSL ran from the shared `/mnt/c` checkout (not a native Linux filesystem benchmark). Unicode display width and Spark's full `ToPrettyString` behavior for nested/complex types remain additional edge cases.

2026-09-30 per-overload evidence: `showNoArgsMatchesSpark`, `showBooleanMatchesSpark`, `showIntMatchesSpark`, and `showIntBooleanMatchesSpark` each isolate one overload with a direct output assertion. `aggSumMatchesSpark` and `getMaxValMatchesSpark` similarly isolate the scalar overloads and compare against Spark with positive, negative, and NULL-bearing values.   '-Dzingg07.contract.profile=true' `
```powershell
  '-Dzingg07.contract.jar=C:/absolute/path/zingg-common-client-0.7.0.jar' test
```

Spark is pinned to 3.5.5 and its declared Scala 2.12.18 runtime. The isolated Zingg v0.7 capsule was compiled against Scala 2.12.10, but Spark reference execution must use Spark's exact patch version: mixing Scala 2.12.10 into Spark caused serialized-lambda failures in Spark's generated shuffle stage. Current differentials compare both `groupByCount` overloads, `countDistinct`, `aggSum`, `getMaxVal`, NULL/non-NULL filters, `filterInCond`, `joinOnCol`, two-key joins, left/right outer joins, prefixed-key joins, `distinct`, `except`, positional `union`/`unionAll`, `unionByName` with reordered and missing columns, full/subset `dropDuplicates`, `withColumn` literals and expressions, simultaneous `withColumns` replacements, ordered `select`, `selectExpr`, duplicate-name `toDF` and arity errors, expression-builder overloads for equality/inequality/comparison and boolean logic, NULL-propagating `concat`, `substr`, column and missing-name `drop`, `withColumnRenamed` with missing-source and target-collision cases, ascending/descending ordering, `orderBy`, `limit`, and row accessors (`get`, numeric/string `getAs*`, `getOnlyObjectFromRow`, `head`, `fieldNames`, `isEmpty`, and `collectFirstColumn`). Accessor fixtures include typed INTEGER/BIGINT/DOUBLE columns, strict-cast failures, NULL and empty strings, primitive access to NULL, an empty frame, and a non-string first column whose `collectFirstColumn` cast must fail as in Spark. Spark and DuckDB both reject primitive access to NULL, although their concrete exception wrappers differ (`SparkException` versus proxy unboxing `NullPointerException`); the adapter remains Spark-free. Fixtures include NULL and empty aggregate inputs, NULL groups/keys/values, NULL sort values, duplicate input/match rows, and unmatched rows; comparisons check output columns, sort-key order, scalar values/error behavior, and normalized full-row multiplicities (or key uniqueness where Spark's retained duplicate row is unspecified). The focused suite is run on Windows and WSL. This is still a selected operation slice, not evidence that the entire `ZFrame` contract or phase outputs have parity.
